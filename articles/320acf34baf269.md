## はじめに

この記事では、オープンソースの個人用AIアシスタント**OpenClaw**のセットアップ手順を、**Claude Code**と一緒に進めた記録をまとめます。

「自分専用のAIアシスタントをローカルで動かしたい」「チャットアプリから自由に操作したい」という方の参考になれば幸いです。

## OpenClawとは

[OpenClaw](https://openclaw.ai/)は、Peter Steinbergerが開発したオープンソースの個人用AIアシスタントです。

主な特徴は以下の通りです。

- **ローカル実行** — Mac / Windows / Linuxで動作し、データはすべて手元に残る
- **複数チャットアプリ対応** — WhatsApp、Telegram、Discord、Slack、Signal、iMessageなどから操作可能
- **永続的メモリ** — ユーザーの好みや文脈を記憶し、パーソナライズされた応答を提供
- **ブラウザ操作** — Webサイトの閲覧、フォーム入力、データ抽出が可能
- **システムアクセス** — ファイル操作、シェルコマンド実行、スクリプト実行に対応
- **スキル＆プラグイン** — コミュニティスキルの利用やカスタムスキルの構築が可能

エンタープライズSaaSに依存せず、自分のマシン上で完全に制御できる「真の個人向けAI」を目指したプロジェクトです。

## セットアップ手順

### 1. OpenClawのインストール

**macOS / Linux:**

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

**Windows（PowerShell）:**

```powershell
iwr -useb https://openclaw.ai/install.ps1 | iex
```

### 2. オンボーディングウィザードの実行

```bash
openclaw onboard --install-daemon
```

このコマンドで以下が一括セットアップされます。

- **認証設定** — APIキーの登録
- **ゲートウェイ設定** — ローカルサーバーの構成
- **チャンネル設定** — チャットアプリとの接続（オプション）
- **デーモンインストール** — バックグラウンドサービスとして登録

`--install-daemon`フラグを付けることで、システム起動時に自動的にOpenClawが立ち上がるようになります。

### 3. Gateway bindの選択

オンボーディング中に、ゲートウェイがどのネットワークで待ち受けるかを選択します。

| 選択肢 | バインドIP | アクセス範囲 | 用途 |
| --- | --- | --- | --- |
| **Loopback** | `127.0.0.1` | 自分のPCのみ | 一人で使う（最も安全） |
| **LAN** | `0.0.0.0` | 同じWi-Fi/LANの全デバイス | スマホや他PCからアクセス |
| **Tailnet** | Tailscale IP | Tailscaleネットワーク内 | 外出先からVPN経由でアクセス |
| **Auto** | Loopback → LAN | 自動判定 | Loopbackで試し、必要ならLANへ |
| **Custom IP** | 任意のIP | 指定したNICのみ | 特定インターフェースに限定 |

迷ったら**Loopback**（デフォルト）で問題ありません。後から変更可能です。

:::message alert
LANを選択すると同じネットワーク上の誰でもアクセスできます。カフェや共有Wi-Fiでは使わないようにしましょう。
:::

### 4. チャンネルの設定

オンボーディングの最後に、チャットアプリとの接続設定を行います。

対応チャンネルの一覧が表示され、現在の接続状態が確認できます。

**標準チャンネル（設定のみで利用可能）:**

| チャンネル | 備考 |
| --- | --- |
| Telegram | Botトークンが必要 |
| WhatsApp | QRコードでペアリング |
| Discord | Botトークンが必要 |
| IRC | サーバー情報を指定 |
| Slack | App設定が必要 |
| Signal | リンクデバイスとして登録 |
| iMessage | macOSのみ対応 |

**プラグインが必要なチャンネル:**

Feishu、Google Chat、Nostr、Microsoft Teams、Mattermost、Nextcloud Talk、Matrix、BlueBubbles、LINE、Zaloなどはプラグインのインストールが必要です。

プラグインの有効化は以下のコマンドで行います（LINEの例）。

```bash
openclaw plugins enable line
```

:::message
npmパッケージとしては公開されていないプラグインもありますが、`openclaw plugins enable`コマンドで内蔵プラグインとして有効化できます。有効化後はゲートウェイの再起動が必要です。
:::

:::message
すべてのチャンネルを一度に設定する必要はありません。後から`openclaw channels login`で追加できます。まずは普段使っているアプリ1つから始めるのがおすすめです。
:::

### 5. ゲートウェイの動作確認

```bash
openclaw gateway status
```

デーモンをインストールしている場合、ゲートウェイはすでに起動しているはずです。ステータスが正常であることを確認しましょう。

### 6. ダッシュボード（Control UI）を開く

```bash
openclaw dashboard
```

もしくはブラウザで直接アクセスできます。

http://127.0.0.1:18789/

ダッシュボードからは、チャンネルの管理やセッションの確認が行えます。

## ワークスペース

オンボーディング完了時に、`~/.openclaw/workspace/`が自動生成されます。これはエージェント（AI）が作業するためのサンドボックス的なディレクトリです。

```
~/.openclaw/workspace/
├── .git/          # 自動でgit initされる
├── .openclaw/     # エージェント用の内部状態（workspace-state.json）
├── AGENTS.md      # エージェントの動作ルール
├── BOOTSTRAP.md   # 初回起動時の初期化手順
├── HEARTBEAT.md   # 定期チェックイン設定
├── IDENTITY.md    # エージェントのアイデンティティ
├── SOUL.md        # AIのペルソナ・性格設定
├── TOOLS.md       # ローカル環境固有のメモ
├── USER.md        # ユーザー情報
└── memory/        # 日次メモリログ（自動生成）
```

ワークスペースには自動で`git init`が実行され、エージェントがファイルを変更した履歴をローカルでgit追跡してくれます。基本的にはローカル完結ですが、リモートリポジトリを追加してバックアップ管理することも可能です。

ワークスペースの場所は`openclaw.json`の`agents.defaults.workspace`で変更できます。

### `openclaw.json`とワークスペースの違い

OpenClawには2種類の設定領域があります。

| | `~/.openclaw/openclaw.json` | `~/.openclaw/workspace/` |
| --- | --- | --- |
| 役割 | **システム全体**の設定 | **エージェント（AI）**の作業環境 |
| 内容 | gateway, channels, model, plugins等 | ペルソナ、メモリ、ツール設定等 |
| 編集する人 | ユーザー | エージェント自身（＋ユーザー） |
| 変更の反映 | ホットリロード | セッション開始時に読み込み |

`openclaw.json`は「OpenClawをどう動かすか」、ワークスペースは「エージェントがどう振る舞うか」を管理します。

### ワークスペースの各ファイル詳細

#### `SOUL.md` — ペルソナ設定

エージェントの**性格・価値観・行動指針**を定義するファイルです。いわば「AIの魂」。

- 応答スタイル（丁寧？カジュアル？皮肉っぽい？）
- 基本原則（「質問する前にまず自分で調べる」「意見を持つ」など）
- 境界線（プライバシーの扱い、外部アクション時の確認ルール）
- エージェント自身が成長とともに更新していくファイル

#### `AGENTS.md` — 動作ルール

エージェントの**セッションごとの行動手順**とルールを定義します。

- セッション開始時の読み込み順序（SOUL.md → USER.md → memory）
- メモリの管理方針（日次ログと長期記憶の使い分け）
- 安全ルール（`rm`より`trash`を使う、外部アクションは確認してから等）
- グループチャットでの振る舞い（発言タイミング、リアクションの使い方）
- ハートビート（定期チェックイン）の活用方法

#### `USER.md` — ユーザー情報

エージェントが覚えておく**ユーザーの情報**です。

- 名前、呼び方、タイムゾーン
- 興味・関心、進行中のプロジェクト
- 好み、癖、嫌なこと

エージェントが会話の中で学んだ内容を随時更新していきます。

#### `IDENTITY.md` — エージェントのアイデンティティ

エージェント自身の**名前・個性**を定義します。

- 名前（エージェントが自分で選ぶ）
- 生き物の種類（AI？ロボット？ゴースト？）
- 雰囲気（シャープ？温かい？カオス？）
- シグネチャ絵文字、アバター画像

#### `TOOLS.md` — ローカル環境メモ

エージェントが使う**環境固有の情報**のメモ帳です。

- カメラの名前と場所
- SSHホスト・エイリアス
- TTS（音声合成）の好みの声
- デバイスのニックネーム

スキル（共有）とローカル設定（個人）を分離するための仕組みです。

#### `BOOTSTRAP.md` — 初回起動手順

エージェントの**初回セットアップ手順**です。

- ユーザーとの最初の会話の進め方
- IDENTITY.md、USER.md、SOUL.mdの初期設定ガイド
- チャンネル接続のガイド
- 初回セットアップ完了後にエージェントが自分で削除する

#### `HEARTBEAT.md` — 定期チェックイン

エージェントが**定期的に確認するタスク**を記載します。

- 空の場合はハートビートAPIコールをスキップ
- タスクを追加するとエージェントが定期的にチェック（メール確認、カレンダー確認など）
- cronジョブとの使い分け：ハートビートは「ゆるい定期チェック」、cronは「正確な時刻指定」

#### `.openclaw/workspace-state.json` — 内部状態

OpenClawが自動管理するファイルで、ワークスペースの初期化状態を記録しています。

```json
{
  "version": 1,
  "bootstrapSeededAt": "2026-02-21T12:43:13.800Z"
}
```

`openclaw setup`コマンドで不足ファイルを再生成する際に参照されます。ユーザーが直接編集する必要はありません。

## エージェントの拡張機能

OpenClawはワークスペースのカスタマイズだけでなく、多くの拡張機能を実装できます。

### マルチエージェント

1つのGatewayで**複数の独立したエージェント**を運用できます。それぞれが別のワークスペース・性格・モデル・権限を持ちます。

```json5
{
  agents: {
    list: [
      { id: "personal", model: "claude-opus-4-6",
        workspace: "~/.openclaw/workspace-personal" },
      { id: "coding", model: "claude-sonnet-4-6",
        workspace: "~/.openclaw/workspace-coding" },
      { id: "family", model: "claude-haiku-4-5",
        tools: { allow: ["read"], deny: ["exec", "write"] } }
    ]
  },
  bindings: [
    { agentId: "personal", match: { channel: "telegram" } },
    { agentId: "coding", match: { channel: "discord", accountId: "coding-bot" } },
    { agentId: "family", match: { channel: "whatsapp",
      peer: { kind: "group", id: "120363...@g.us" } } }
  ]
}
```

チャンネル、送信者、Discordサーバー/ロール単位でメッセージを特定エージェントにルーティングできます。

### メモリ機能

| 機能 | 説明 |
| --- | --- |
| 日次ログ | `memory/YYYY-MM-DD.md`に日々の記録を追記 |
| 長期記憶 | `MEMORY.md`に厳選された永続情報を保存 |
| セマンティック検索 | ベクトルインデックス + BM25のハイブリッド検索 |
| 時間減衰 | 古いメモリのスコアを自動で下げる（30日半減期） |
| 自動保存 | セッション圧縮前に自動でメモリをファイルに書き出し |

### 自動化（Cron・Heartbeat）

| 機能 | 説明 |
| --- | --- |
| Heartbeat | ゆるい定期チェック（メール、カレンダーなど） |
| Cronジョブ | 正確な時刻指定でタスク実行 |
| Webhooks | 外部サービスからのイベント受信 |
| ブラウザ操作 | Webサイトの閲覧・フォーム入力・データ抽出 |

### その他

- **Skills / Plugins / MCP** — ツール・チャンネルの拡張
- **Voice Wake** — 音声による起動
- **マルチメディア** — 画像・音声・位置情報の送受信
- **モデルフェイルオーバー** — LLMプロバイダー間の自動切り替え
- **サンドボックス** — Dockerコンテナでエージェントを分離実行

## ディレクトリ構成の全体像

OpenClawの各データがどこに保存されるかの全体像です。

```
~/.openclaw/
├── openclaw.json              ← システム全体の設定
├── update-check.json          ← アップデートチェックの最終実行日時
├── .claude/                   ← Claude Code連携用の設定
│
├── agents/                    ← エージェントごとの状態管理
│   └── <agentId>/
│       ├── agent/
│       │   ├── auth.json          ← エージェント個別の認証情報
│       │   └── auth-profiles.json ← 認証プロファイル
│       └── sessions/              ← セッション履歴（JSONL形式）
│
├── browser/                   ← ヘッドレスブラウザのユーザーデータ
│   └── clawd/user-data/       ← Chromiumプロファイル（Cookie、キャッシュ等）
│
├── canvas/                    ← ダッシュボード用のWebアセット
│   └── index.html
│
├── credentials/               ← OAuth・ペアリング用の認証情報
│
├── cron/                      ← 定期実行ジョブ
│   ├── jobs.json              ← ジョブの定義
│   └── runs/<jobId>.jsonl     ← 実行ログ
│
├── devices/                   ← モバイルノード（iOS/Android）の接続管理
│   ├── paired.json            ← ペアリング済みデバイス
│   └── pending.json           ← ペアリング待ちデバイス
│
├── identity/                  ← このOpenClawインスタンスの識別情報
│   ├── device.json            ← デバイスID・マシン情報
│   └── device-auth.json       ← デバイス認証トークン
│
├── logs/                      ← Gatewayログ
│   ├── gateway.log            ← 標準出力ログ
│   ├── gateway.err.log        ← エラーログ
│   └── config-audit.jsonl     ← 設定変更の監査ログ
│
├── media/                     ← メディアファイルの一時保存
│   └── inbound/               ← チャットで受信した画像・動画等
│
├── memory/                    ← セマンティック検索用のベクトルDB
│   └── main.sqlite            ← SQLiteベースのメモリインデックス
│
├── skills/                    ← インストール済みスキル（シンボリックリンク可）
│
└── workspace/                 ← エージェントの作業場所
    ├── .openclaw/             ← ワークスペース内部状態
    ├── SOUL.md, AGENTS.md等   ← ペルソナ・動作ルール
    └── memory/                ← 日次メモリログ（Markdown）
```

### 各ディレクトリの役割

| ディレクトリ | 役割 | 誰が管理 |
| --- | --- | --- |
| `agents/` | エージェントごとの認証情報・セッション履歴。マルチエージェント構成では`agents/main/`、`agents/coding/`のように分かれる | OpenClaw自動管理 |
| `browser/` | ブラウザ操作ツール用のChromiumプロファイル。Cookie・キャッシュ・ログイン状態が保持される | OpenClaw自動管理 |
| `canvas/` | ダッシュボード（Control UI）のWebアセット | OpenClaw自動管理 |
| `credentials/` | チャンネル接続のOAuthトークンやペアリング情報（Discord、WhatsApp等） | onboard/channels loginで生成 |
| `cron/` | 定期実行ジョブの定義と実行ログ。`openclaw cron add`で管理 | CLI/エージェント |
| `devices/` | iOS/Androidのモバイルノードとのペアリング状態 | OpenClaw自動管理 |
| `identity/` | このOpenClawインスタンス固有のデバイスID・認証トークン | onboard時に自動生成 |
| `logs/` | Gatewayの標準出力・エラーログ・設定変更の監査ログ | OpenClaw自動管理 |
| `media/` | チャットで送受信したメディアファイルの一時保存先 | OpenClaw自動管理 |
| `memory/` | セマンティック検索用のSQLiteベクトルインデックス。workspaceの`memory/`（Markdown）とは別物 | OpenClaw自動管理 |
| `skills/` | スキルの格納先。シンボリックリンクで外部ディレクトリを参照することも可能 | ユーザー/CLI |
| `workspace/` | エージェントのホームディレクトリ。ファイル操作・コンテキストの起点 | エージェント＋ユーザー |

:::message
`memory/main.sqlite`（ルート直下）と`workspace/memory/`（ワークスペース内）は別物です。前者はセマンティック検索用のベクトルインデックス、後者はエージェントが書く日次のMarkdownログです。
:::

:::message
ワークスペースは閉じた世界ではなく、エージェントはワークスペース外の任意のパスにもアクセスできます。ワークスペースはあくまで「ホームディレクトリ」のような位置づけです。
:::

## 設定ファイル

OpenClawの設定はJSON5形式のファイルで管理されます。ファイルがない場合は安全なデフォルト値が使われます。

| OS | 設定ファイルのパス |
| --- | --- |
| macOS / Linux | `~/.openclaw/openclaw.json` |
| Windows | `%USERPROFILE%\.openclaw\openclaw.json` |

主な設定項目は以下の通りです。

| カテゴリ | 説明 |
| --- | --- |
| チャンネル設定 | WhatsApp, Telegram, Discord, Slackなどの接続設定 |
| モデル設定 | プライマリモデルとフォールバックの指定 |
| アクセス制御 | `dmPolicy`: pairing / allowlist / open / disabled |
| セッション管理 | `dmScope`で会話の継続性を制御 |
| 自動化 | cronジョブ、webhooks、ハートビート |
| サンドボックス | Dockerコンテナでの分離実行 |

設定変更はホットリロードに対応しており、ほとんどの変更は再起動なしで反映されます。

:::details 環境変数（オプション）

カスタムパスが必要な場合は、以下の環境変数で制御できます。

| 変数名 | 用途 |
| --- | --- |
| `OPENCLAW_HOME` | ホームディレクトリの指定 |
| `OPENCLAW_STATE_DIR` | 状態ディレクトリのオーバーライド |
| `OPENCLAW_CONFIG_PATH` | 設定ファイルパスのオーバーライド |
:::

## VPSデプロイ（常時稼働）

ローカルPCの電源に依存せず、**24時間いつでもOpenClawにアクセスできる**構成です。VPSにGatewayを配置し、Cloudflare Tunnelで安全に外部公開します。

### アーキテクチャ

```
ローカルPC（管理用）
  ↓ rsync/ssh で設定・workspace同期

VPS（Ubuntu）
  └── OpenClaw Gateway（localhost:18789）
        ↓
  └── cloudflared daemon（Cloudflare Tunnel）
        ↓
Cloudflare Edge（HTTPS自動化）
  └── openclaw.yourdomain.com
        ↓
Discord / Telegram / LINE / ブラウザ等
```

ポイントは、VPS上のGatewayは`localhost`にバインドしたまま、Cloudflare Tunnelが外部からのアクセスを安全に中継する点です。ポートの直接公開やSSL証明書の管理が不要になります。

### Phase 0: ドメイン取得 + Cloudflare設定

Cloudflare Tunnelの永続利用にはドメインが必要です。

1. ドメインを取得（Cloudflare Registrar、Namecheap等）
2. Cloudflareのダッシュボードでドメインを追加
3. ネームサーバーをCloudflareに向ける（レジストラ側で設定）

:::message
ドメインなしでも`cloudflared tunnel --url http://localhost:18789`で一時URL（`https://xxxxx.trycloudflare.com`）を発行できます。ただしURLは毎回変わるため、テスト用途に限られます。
:::

### Phase 1: VPSにOpenClawをインストール

```bash
# Node.js 22+をインストール（Ubuntu）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

# OpenClawをインストール
curl -fsSL https://openclaw.ai/install.sh | bash

# 初期セットアップ（loopback + token認証）
openclaw onboard --install-daemon
```

オンボーディングでは以下を選択します。

| 項目 | 推奨設定 |
| --- | --- |
| bind | **Loopback**（Cloudflare Tunnelが外部公開を担当） |
| auth | **Token**（APIアクセスの認証） |

### Phase 1.5: ローカルからVPSへ設定を同期

ローカルで育てた設定をVPSに持っていきます。**すべてのファイルをコピーするのではなく、同期するものを選別する**のが重要です。

```bash
# 同期するもの
rsync -avz ~/.openclaw/openclaw.json  vps:~/.openclaw/
rsync -avz ~/.openclaw/workspace/     vps:~/.openclaw/workspace/
rsync -avz ~/.openclaw/cron/          vps:~/.openclaw/cron/

# 同期しないもの（VPS側で自動生成される）
# - identity/    ← デバイス固有のID・鍵ペア
# - devices/     ← ペアリング済みデバイス情報
# - credentials/ ← チャンネルのOAuthトークン等
```

:::message alert
`identity/`はデバイス固有のEd25519鍵ペアを含みます。ローカルとVPSで共有すると認証の競合が起きるため、必ずVPS側で`openclaw onboard`時に別途生成させてください。
:::

:::message alert
`openclaw.json`にDiscordトークンなどの機密情報が平文で含まれている場合は、VPSでは環境変数に分離することを強く推奨します（Phase 5で解説）。
:::

### Phase 2: systemdサービス化

VPSの再起動後も自動でGatewayが起動するよう、systemdサービスを設定します。

```bash
sudo tee /etc/systemd/system/openclaw-gateway.service > /dev/null << 'EOF'
[Unit]
Description=OpenClaw Gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=YOUR_USERNAME
Environment=HOME=/home/YOUR_USERNAME
Environment=OPENCLAW_HOME=/home/YOUR_USERNAME/.openclaw
ExecStart=/usr/local/bin/openclaw gateway --port 18789
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

```bash
# YOUR_USERNAMEを実際のユーザー名に置換してから実行
sudo systemctl daemon-reload
sudo systemctl enable openclaw-gateway
sudo systemctl start openclaw-gateway

# 動作確認
sudo systemctl status openclaw-gateway
```

:::message
`ExecStart`のパスは`which openclaw`で確認してください。`nvm`等でNode.jsをインストールした場合はパスが異なります。
:::

### Phase 3: Cloudflare Tunnel設定

#### 3-1. cloudflaredのインストール

```bash
# Debian/Ubuntu
curl -L --output cloudflared.deb \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
```

#### 3-2. Cloudflare認証 + トンネル作成

```bash
# ブラウザが開くのでCloudflareアカウントで認証
cloudflared tunnel login

# トンネル作成
cloudflared tunnel create openclaw
```

`cloudflared tunnel create`を実行すると、トンネルIDとクレデンシャルファイルが表示されます。このIDを控えておきます。

#### 3-3. トンネル設定ファイルの作成

```bash
mkdir -p ~/.cloudflared

cat > ~/.cloudflared/config.yml << EOF
tunnel: YOUR_TUNNEL_ID
credentials-file: /home/YOUR_USERNAME/.cloudflared/YOUR_TUNNEL_ID.json

ingress:
  - hostname: openclaw.yourdomain.com
    service: http://localhost:18789
    originRequest:
      noTLSVerify: true
  - service: http_status:404
EOF
```

`YOUR_TUNNEL_ID`、`YOUR_USERNAME`、`yourdomain.com`は実際の値に置き換えてください。

#### 3-4. DNSレコードの作成

```bash
cloudflared tunnel route dns openclaw openclaw.yourdomain.com
```

このコマンドでCloudflareのDNSにCNAMEレコードが自動作成されます。

#### 3-5. cloudflaredのsystemdサービス化

```bash
sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared
```

```bash
# 動作確認
sudo systemctl status cloudflared

# 外部からアクセス確認
curl https://openclaw.yourdomain.com
```

### Phase 4: ローカルからの管理設定

VPSにデプロイした後も、ローカルから設定を管理できます。

#### rsync同期スクリプト

```bash
#!/bin/bash
# sync-to-vps.sh — ローカルの設定をVPSに同期

VPS_HOST="your-vps-host"
REMOTE_HOME="~/.openclaw"

echo "==> openclaw.json を同期中..."
rsync -avz ~/.openclaw/openclaw.json "$VPS_HOST:$REMOTE_HOME/"

echo "==> workspace を同期中..."
rsync -avz --exclude='.git' ~/.openclaw/workspace/ "$VPS_HOST:$REMOTE_HOME/workspace/"

echo "==> cron を同期中..."
rsync -avz ~/.openclaw/cron/ "$VPS_HOST:$REMOTE_HOME/cron/"

echo "==> VPSのGatewayを再起動中..."
ssh "$VPS_HOST" "sudo systemctl restart openclaw-gateway"

echo "✓ 同期完了"
```

```bash
chmod +x sync-to-vps.sh
./sync-to-vps.sh
```

#### ローカルの`openclaw.json`をリモートモードに切り替え

ローカルのOpenClawをリモートのGatewayに接続する場合は、`gateway.mode`を`remote`に変更します。

```json5
{
  gateway: {
    mode: "remote",
    remoteUrl: "https://openclaw.yourdomain.com",
    // port, bind等のローカルGateway設定はremoteモードでは無視される
  }
}
```

### Phase 5: セキュリティ強化

#### SSH鍵認証のみに制限

```bash
# /etc/ssh/sshd_config を編集
sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart sshd
```

#### UFWファイアウォール設定

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
# Cloudflare Tunnelは外向き接続なので、追加のポート開放は不要
sudo ufw enable
```

:::message
Cloudflare Tunnelはcloudflaredから**外向きに**Cloudflareへ接続するため、VPSで18789番ポートを外部に開放する必要はありません。これがリバースプロキシとの大きな違いです。
:::

#### 機密情報の環境変数化

`openclaw.json`に含まれるトークン類を環境変数に分離します。

```bash
# /etc/systemd/system/openclaw-gateway.service の[Service]セクションに追加
Environment=DISCORD_BOT_TOKEN=your_discord_token_here
```

もしくは、専用のenvファイルを使う方法もあります。

```bash
# /etc/openclaw/env に機密情報を格納
sudo mkdir -p /etc/openclaw
sudo tee /etc/openclaw/env > /dev/null << 'EOF'
DISCORD_BOT_TOKEN=your_discord_token_here
EOF
sudo chmod 600 /etc/openclaw/env
```

```ini
# systemdサービスファイルで読み込み
[Service]
EnvironmentFile=/etc/openclaw/env
```

:::message
環境変数名はOpenClawの設定に対応させる必要があります。対応する変数名はOpenClawのドキュメントを確認してください。
:::

#### Cloudflare Access（オプション）

Cloudflare Accessを使うと、Tunnelの手前にメール認証やOAuthなどの追加認証レイヤーを設置できます。ダッシュボード（Control UI）へのアクセスを制限する場合に有効です。

:::message alert
Cloudflare AccessをWebSocket経由のチャットパスに適用すると、認証チャレンジがWebSocket接続を妨げる場合があります。チャット用のパスにはBypassルールを設定してください。
:::
